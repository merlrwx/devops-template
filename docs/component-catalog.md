# Reference component catalog

This catalog audits the working `devops-app` and `devops-app-gitops` checkouts as
they exist now. Paths below are relative to the named repository. Inclusion
classes describe template suitability: **Reusable** is a sound default or
portable pattern; **Optional** is useful when the project chooses that capability;
**Project-specific** needs explicit adaptation; **Unsuitable** should not be
copied as-is.

## Selection guidance

Mise, appropriate tests/lint/pre-commit checks, and language-specific app code
form the shared foundation. Choose the API/UI shape to fit the application;
Compose only for local multi-service use; containers for image delivery or
container-based development; GitHub Actions only for GitHub; Kubernetes only
for Kubernetes deployments; Flux only for GitOps-managed Kubernetes. Flux
depends on Kubernetes. Release automation, security scans, K3d helpers and
production promotion remain optional and should match the project's needs.

The dotfiles project's `dot_codex/skills/project-scaffold/references/selection-rules.md`
and `dot_codex/skills/project-scaffold/SKILL.md` use these same dependency
boundaries: inspect first, choose the smallest valid combination, and do not
infer Kubernetes, Flux or infrastructure provisioning. This catalog describes
observed reference components; it does not assert that each belongs in every
generated project.
